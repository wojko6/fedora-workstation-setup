# Fedora 45 / NVIDIA 620.70.06 — read-only upgrade preflight (2026-11-04)

> **Evidence:** operator-supplied Fedora 44 KDE/DNF5 console results on 2026-11-04; not CI, a clean-room target VM, or a validated major upgrade. **No RPM transaction** was authorized. `INSTALLATION_GATE=HOLD`, `FEDORA_UPGRADE_STARTED=NO`. This record does **not** update the accepted GNOME-based desired-state baseline of this repository.

## Scope and status

- Source system: Fedora 44 KDE/Wayland workstation with RPM Fusion proprietary NVIDIA `610.57.04`; ten DNF5 version locks pin corresponding `3:610.57.04-1.fc44` packages. Previous suspend/monitor regression makes driver/runtime verification a separate gate.
- Target: Fedora 45 packages, with a locally staged `620.70.06-1.fc45` NVIDIA set; all checks use read-only RPM queries, `repoquery`, or `distro-sync --assumeno` and do not establish deployment suitability.
- A later `mokutil --sb-state` read returned **SecureBoot disabled**, while prior checkpoints had indicated enabled. Timing/cause of the change is not established. This does not retroactively alter accepted baselines or authorize firmware changes.

## NVIDIA solver audit, B1–B6

1. **B1 / initial full transaction:** ten FC44 NVIDIA version locks coincide with newer FC45 candidates: `akmod-nvidia` 615.71.09 from the standalone driver repository and 615.78.08 from standard RPM Fusion; the solver failed with an open akmod/common dependency and driver packages filtered out.
2. **B2/B3 / full distro-sync summary:** with the standalone NVIDIA driver repository and VPCS COPR disabled, DNF5 computed a transaction of **70 installs, 3578 upgrades, 3610 replacements, 16 downgrades, one dependent removal**, roughly **6 GiB incoming** and **759 MiB net additional disk usage**. The transaction was canceled as designed by `--assumeno` (`DNF_RC=1`), not installed.
3. **B3 downgrade review:** NetworkManager-l2tp (2), Akonadi Calendar (1), BIND (2), GitHub CLI (1), HPLIP/libsane (4), Kirigami/QuickImageEditor (2), Wireshark (2), Xen (2). Not blanket-approved: networking and security impact still needs review.
4. **B4:** the B3 transaction log contained **no NVIDIA driver change entries**; a successful solver with unchanged NVIDIA 610 does not establish a usable driver after booting an FC45 kernel.
5. **B5:** main/repo `excludepkgs` and `includepkgs` fields were empty. `--disable-plugin=versionlock` emitted an unrecognized libdnf-plugin warning; do **not** claim it bypassed version locks. Query results alone cannot establish transaction-level lock bypass.
6. **B6:** focused `distro-sync ... --assumeno` using `--setopt='disable_excludes=*'` and disabling the standalone NVIDIA driver repository **proposed a consistent `615.78.08-1.fc45`** driver set including CUDA and both x86_64/i686 libraries; no reported solver failure. This checks candidate resolution, **not** 620 compatibility, installation, signed kernel module, or runtime.

## Local NVIDIA 620.70.06 lab, B7–B8

- A local Fedora 45 repository was found in an existing *isolated solver workspace* with valid `repomd.xml` and **16 RPM files**. It was **not** registered as a persistent repo on the host.
- Packages include `akmod-nvidia` 620.70.06, a prebuilt `kmod-nvidia-7.2.15-300.fc45.x86_64`, `nvidia-modprobe`, `nvidia-persistenced`, `nvidia-settings`, primary driver/CUDA, power and kmodsrc components, and x86_64 + i686 variants of NVIDIA/CUDA libraries.
- DNF5 temporary `--repofrompath` query could see `akmod-nvidia`, main NVIDIA driver and both library architectures.
- `rpm -K` printed **checksum OK** for three *selected* RPM files (akmod, prebuilt kernel module, main driver); this is **not** a trusted signature/provenance or full 16-package verification and does not demonstrate the module loads on the actual Fedora 45 kernel.

## Hard gates and next checkpoint

- **B9 full Fedora 45 transaction solver with the local 620 repository was proposed but NOT RUN in supplied evidence.** No `B9=PASS` claim.
- Before any upgrade authorization: simulate full transaction with target repo and ensure every NVIDIA driver/CUDA library uses **620**, not a mixed 615/620 stack; validate target kernel and module ABI, akmods compilation path, signatures/trust as relevant to the observed Secure Boot state, rollback/backup, VPCS retention and scrcpy runtime.
- Preserve visibility into the 16 downgrades and sole removal; do not automatically use `--skip-broken`, `--allowerasing`, or blind package cleanup.
- Verify physical KDE/Wayland, external DP monitor, suspend/resume, networking and other workstation acceptance separately; a solver PASS alone is insufficient.

**End state as reported:** running Fedora 44/NVIDIA 610 remains unchanged, version locks unchanged, no Fedora 45 upgrade, and `INSTALLATION_GATE=HOLD`.
