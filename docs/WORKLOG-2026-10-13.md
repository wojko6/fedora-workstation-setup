## NVIDIA 615 re-upgrade regression: controlled return to 610 and boot safety

**Status:** operator remediation complete; display-off/on and one `deep` suspend/resume passed after booting NVIDIA 610.57.04 + kernel 7.2.9-200. **Long-run reliability and KDE screen-lock defect remain open**.

**Full evidence and remediation record:** [2026-10-13 incident report](incidents/2026-10-13-nvidia-615-resume-regression.md). Prior state and known `kscreenlocker_greet` SIGSEGV: [2026-10-11 worklog](WORKLOG-2026-10-11.md). ## Incident and diagnosis

- DNF transaction **118** updated **267** packages on the Fedora 44 physical host and replaced the manually restored **NVIDIA 610.57.04** with **615.71.09**, alongside installation of kernel **7.2.9-201**.
- No DNF5 NVIDIA version-lock rules were present before this update; automatic package lifecycle allowed the re-upgrade.
- After the display went dark, the previous boot's journal contained `PowerDevil: There are no outputs`, an NVIDIA `Lost display notification` warning, KWin delay-inhibitor timeout and `PM: suspend entry (deep)` at **11:38:04**, but not a confirmed normal suspend exit in the inspected excerpt. Services continued producing logs. Attribution to a specific component remains **unproven**.
- Current NVIDIA parameters before remediation included `UseKernelSuspendNotifiers=1`, explaining the expected `nvidia-suspend.service` skip; `s2idle [deep]` selected deep.

## Verified repair

1. Verified **all 12** archived NVIDIA 610 RPM files with `rpm -K`: digest/signature checks OK.
2. Dry-run downgrade without erasing found a conflict with the 615 kernel-specific kmod for **7.2.9-201**; adding `--allowerasing` produced an isolated transaction: **12 package downgrades + removal of exactly one 615 kmod**, no unrelated removals.
3. Preserved installed kernels and selected **7.2.9-200** as the default with `grubby`, because its prebuilt NVIDIA kernel module was verified as **610.57.04**. Kernel 7.2.9-201 was not deleted.
4. Performed the reviewed DNF5 downgrade successfully and added **10 exact-EVR versionlock rules** for the installed NVIDIA 610 package set.
5. Rebooted; the loaded NVIDIA open module and `nvidia-smi` matched **610.57.04**; running kernel **7.2.9-200**, KDE Wayland session active, **0** failed system/user units.
6. KDE automatic display off/on and an explicit `systemctl suspend` / wake both succeeded. Kernel journal: **12:25:57** `PM: suspend entry (deep)` → **12:26:40** `PM: suspend exit`; systemd reported return from sleep and service deactivation success.
7. Set DNF5 `installonly_limit=5` (previously 3), kept `protect_running_kernel=1`. Final `/boot`: **997 MB available of 2.0 GB**; default kernel remains **7.2.9-200**.
