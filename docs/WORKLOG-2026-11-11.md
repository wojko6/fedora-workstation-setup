## Plasma configuration sidebar — distinct system-file change

The physical `plasma-desktop-6.8.2-1.fc45.x86_64` configuration QML sets the sidebar categories width to `Kirigami.Units.gridUnit * 7`. A user-applied modification targeted roughly `* 10`. The subsequent screenshot shows legible Polish category labels without single-character line wrapping: `SIDEBAR_VISUAL=PASS_BOUNDED`.

This QML belongs to the **RPM-managed Plasma desktop package**, unlike the user-scoped gettext patches. It affects applet configuration dialogs more generally, and updates/reinstallation may overwrite it. The script's final install/backup output was not pasted; the visual change does not independently prove backup existence or record the exact modified file hash. Do not claim it is a version-pinned, reproducible configuration.

## Logout observation

Using `loginctl terminate-session` to force the active session closed was reported to leave the graphical environment unusable while TTY access remained available. This is not proof of a kernel or full-machine hang or of a unique cause. The Tahoe top-panel logout item **did** display the normal KDE logout confirmation dialog; an end-to-end logout via that menu was not separately validated. Prefer standard KDE logout for future UI tests.

## AppBay + Krema native Launchpad — bounded operator acceptance

The same Fedora 45 / KDE Plasma 6.8.2 / Wayland workstation gained an application grid inspired by macOS Launchpad. The operator tested the [Plasma-AppBay](https://github.com/zayronxio/Plasma-AppBay) plasmoid with Krema 0.13.0. Initially, standalone `plasmawindowed` displayed a secondary compact Apple-logo host window and had inconsistent perceived scrolling smoothness. A per-process `QSG_RENDER_LOOP=basic` test was subjectively smoother, but **180-FPS animation was never established**. Experimental hiding / `--statusnotifier` behavior caused stale hidden instances and was rolled back.

A native AppBay instance in `plasmashell` first displayed a blurred background without the full applications grid; search matches worked. A local guarded JSON group-settings read and later an **`onRefreshed`-based `Kicker.RootModel` regeneration** replaced unsuccessful timeout retries. Following a controlled Plasma shell reload, the diagnostic reported **`root=13 source=154 grid=154`**, and the operator visibly confirmed the initial grid, page navigation and `Esc` closure. Some startup QML null-model warnings remained in the logs.

The operator registered a shortcut for the native applet and confirmed the D-Bus `org.kde.kglobalaccel.Component.invokeShortcut` action works. The existing Krema-pinned `appbay-basic.desktop` now uses the action for **applet ID 100** instead of starting `plasmawindowed`. This ID is specific to the current panel configuration and must be re-discovered following applet replacement. The native panel applet remains installed with an invisible compact icon, and AppBay's own Favorites dock is disabled. The operator confirmed a one-click Krema launch, native grid and working `Esc` behavior, with no extra Apple-logo window in the accepted path.

**Evidence:** operator-supplied UI images, terminal commands, applet config readouts and model-refresh logs. **Boundaries:** no measured native 180 FPS, no independent post-reboot/session longevity or clean-room rebuild; local QML changes and preferences are not yet version-pinned restore artifacts. The existing Fedora 45/KDE reproducible desired-state gate remains **HOLD**. No additional issue was opened, no live host command was run by this GitHub update, and no source/runtime changes are committed here.

**Details and operator-only recovery notes:** [KDE native AppBay + Krema technical record](kde-appbay-krema-launchpad-2026-11-11.md).

## MacTahoe SDDM v0.4 — physical display-manager migration and login

The operator staged a local Polish MacTahoe Qt 6 greeter on Fedora 45 / KDE Plasma 6.8.2 / Wayland, after reviewing [upstream MacTahoe](https://github.com/vinceliuice/MacTahoe-kde) and its Plasma 6.8 `VirtualKeyboardLoader` incompatibility ([issue #21](https://github.com/vinceliuice/MacTahoe-kde/issues/21)). In a dedicated preview, the locally adapted theme displayed a Tahoe background, Polish date/power labels and a selectable Plasma session. A separate source/installer check staged the `Fedora-MacTahoe-v04` theme with a backup while the system was still using GDM.

The operator's read-only checks confirmed SDDM's Wayland/KWin configuration, `[Theme] Current=Fedora-MacTahoe-v04`, a usable external `DP-1` 2560×1440@180 Hz output, and the SDDM service account's copied output configuration. Following the actual GDM → SDDM enablement and reboot, a Plasma Setup screen appeared first; a later photograph demonstrated the actual MacTahoe login screen on the external display. The intervening setup-screen resolution was not independently evidenced by terminal output.

**The operator then successfully logged in to KDE Plasma/Wayland.** Subsequent host output reported `sddm.service` as `enabled` and `active`, `XDG_CURRENT_DESKTOP=KDE`, `XDG_SESSION_TYPE=wayland`, and system/session language `pl_PL.UTF-8`. Two Qt `sddm-helper` warnings about an initial `C` locale falling back to `C.UTF-8` were non-blocking in that login attempt. The live greeter's white avatar and cyan password field differ from preview screenshots; power-button actions, incorrect-password messaging and the documented GDM rollback were not exercised.

**Gate:** `SDDM_REAL_LOGIN=PASS_OPERATOR_PHYSICAL`; `SDDM_ROLLBACK=DOCUMENTED_NOT_TESTED`; `FEDORA45_KDE_REPRODUCIBLE_RESTORE=HOLD`. See [technical deployment record](kde-mactahoe-sddm-2026-11-11.md). No additional issue, host-side action or runtime artifact was created by this documentation update.
