# Worklog — 2026-11-13 (Finder KDE LAB: Graphite UI audit and A.4/A.5 visual gate)

> **Scope:** bounded, application-only Finder KDE LAB experiment on a physical Fedora 45 / KDE Wayland host. This is a partial daily checkpoint, not a system release or a reproducible clean-room restore.
> **Evidence:** operator-reported SHA-256 and test outputs, manual screenshots and read-only source excerpts; separate assistant-side synthetic generator tests. No GitHub action ran a GUI test on the workstation.
> **Publication:** sanitized; no private paths, filenames, log payloads, secrets, screenshots or user configurations are committed.

## Intent and confirmed improvements

- The operator adopted a **matte, neutral Graphite** visual direction, retaining recognizable blue sidebar icons and existing Finder behaviors. The existing translucent custom sidebar was painted in Finder's C++ chrome, not by the hidden standard KDE Places view. A v0.5 A candidate changed the sidebar surface to an opaque graphite tone and visually removed the earlier violet tint.
- A v0.5 A isolated source build passed (`BUILD_EXIT_CODE=0`). ELF `RUNPATH` and operator `ldd` output resolved the private Dolphin libraries from the matching build directory without missing direct dependencies. This is not complete plugin/runtime acceptance.
- A.1 added a candidate full-label tooltip for truncated sidebar bookmarks; its isolated build passed (`GRAPHITE_A1_BUILD=PASS`). Actual tooltip and cloud-status GUI behavior remain **PENDING**.
- Initial double navigation docks were observed with an existing profile; a fresh test profile showed the custom Finder sidebar alone. This is consistent with saved layout versus first-run behavior, but F7 persistence was **not** independently established. No unconditional dock-hiding change was applied.

## Search and color-profile constraints

- A.3 search-control-only QSS candidate passed self-test, safety guards and generated-file integrity checks. Its first launch under an incompletely themed fresh XDG profile showed pale address controls and unreadable file labels. Re-running after seeding a **copy** of the KDE palette and restoring local theme lookups produced legible dark controls. This indicates a profile/theme confounder; it is not evidence that the A.3 QSS alone caused the original mismatch.
- Full search-row scope/filter, keyboard-focus and search behavior acceptance remain **PARTIAL / NOT RUN**. The previously accepted compact progress behavior must be preserved.

## A.4 path editor and A.5 external MIME editor

- A.4 and A.5 were prepared in an isolated LAB and passed operator-reported preflight and artifact integrity checks: `A4_ADDRESS=PASS_INTEGRITY`, `A5_MIME=PASS_INTEGRITY`, `PRIVATE_BRIDGE=PASS_INTEGRITY`, `RESULT=PASS_CANDIDATES_VERIFIED_ISOLATED`. No local source/launcher changes were reported as part of candidate preparation.
- A.4 adds widget-scoped QSS for the local-path `DolphinUrlNavigator` / `KUrlComboBox` editing surface while keeping existing `remote:/` handling and its state-restoration code unchanged. Operator screenshots demonstrate a dark editable path and working basic local navigation; **field padding, border geometry, height and trailing controls remain visually inconsistent**. The remote network panel and native KNetAttach wizard were displayed, but complete SMB transport and remote/local/remote regression are **not validated**.
- A.5 styles an independent external KDE file-type editor via a per-process private wrapper. Screenshots show a dark dialog, but **the top filename-pattern group appears clipped/obscured** and its text/control spacing is inconsistent. Wrapper activation with an observed `-stylesheet` process argument was not provided; the UI image alone does not prove which stylesheet loaded. MIME associations were **not changed**.
- The Finder-owned Properties dialog remains a distinct surface. Its Sharing tab contains an **Enable Samba service** action whose button style does not match neighboring graphite controls. This is a styling observation only; Samba was **not enabled** and the owning KDE widget/plugin has not been established. The separate native network wizard also retains different visual language; no system-wide restyling is authorized.

## Assessment and explicit gates

**Assessment:** isolated Finder prototype, solid static/build evidence and an accepted matte-sidebar direction; **A.4 and A.5 are not ready for release or default-launcher promotion**. More QSS layers without a shared style contract would obscure ownership and regress native Qt behavior.

Next staged design:
1. **A.8 token specification first:** define one documented graphite surface, field, button, border, focus, selected, disabled and text palette and control rhythm. Qt QSS is not CSS custom-property compatible; use reviewed mappings, not assumed runtime `var()` support.
2. **A.6 address control:** target the concrete navigator and editor widgets, respecting the known remote-frame v2.2.2 state-preservation logic; verify breadcrumb/edit, Ctrl+L, Enter/Esc, active/inactive/focus, complete local↔remote transitions, accessibility and KNetAttach behavior.
3. **A.7 dialog harmonization:** inspect actual dialog/widget hierarchy and why MIME filename-pattern elements clip (including fixed size constraints) before changing padding; include separate Finder Properties, special Samba action and private external file-type editor. Do not modify KDE packages or enable services.
4. Each experiment must use a separately pinned build/QSS, explicit operator GUI screenshots, an optional rollback and a no-write test profile. No global Qt/KDE style overrides.

**Gates:** `MATTE_A_VISUAL_DIRECTION=ACCEPTED`; `A1_TOOLTIP_GUI=PENDING`; `A2_LAYOUT_PERSISTENCE=PENDING`; `A3_SEARCH_GUI=PARTIAL`; `A4_A5_GUI=REVIEW_REQUIRED`; `DEFAULT_FINDER_PROMOTION=HOLD`; `FEDORA45_KDE_REPRODUCIBLE_RESTORE=HOLD`. No installation, global icon/theme change, merge or new issue is part of this entry.
