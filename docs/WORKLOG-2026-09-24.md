## Desktop-environment plan revision

The earlier concept of maintaining two GNOME visual profiles was superseded by a stronger engineering target:

1. preserve the current accepted GNOME workstation as the canonical baseline;
2. add KDE Plasma later as an optional, reproducible alternate desktop session.

The first implementation phase must not replace GNOME or change the display manager at the same time.

The future validation scope includes:

- GNOME -> KDE -> GNOME session switching;
- rollback to the accepted GNOME baseline;
- XDG portals;
- MIME and default-application behavior;
- keyring/KWallet behavior;
- autostart interactions;
- Wayland session behavior;
- networking and Tailscale;
- audio and Bluetooth;
- removable storage;
- reproducible KDE configuration capture and restore;
- full repository verifier execution after the change.

Until those checks pass, KDE Plasma is a planned feature only and is not part of the accepted Fedora desired state.

## Firewalld / Tailscale isolation finding

Issue #11 was advanced with a live read-only audit followed by a bounded A/B hardening test.

### Initial state

The trusted Wi-Fi interface remained correct:

```text
wlp4s0 -> workstation-kdeconnect

services:
dhcpv6-client
kdeconnect
mdns

forward: no
masquerade: no
explicit ports: none
rich rules: none
```

The broader default zone remained:

```text
FedoraWorkstation (default)

services:
dhcpv6-client
samba-client
ssh

ports:
1025-65535/udp
1025-65535/tcp

forward: yes
```

The Tailscale interface had no explicit firewalld zone:

```text
tailscale0 -> no zone
```

Tailscale itself was operating with:

```text
nf=on
```

The nftables inspection showed the Tailscale chains running before firewalld, while unmatched interface traffic still reached firewalld's default-zone dispatch.

### Listener correlation

Local listener inspection confirmed that SSH was not actually running, but several high-port listeners existed.

Relevant examples included:

```text
GSConnect / gjs:
TCP/1716
UDP/1716

Steam:
TCP/27036
UDP/27036
```

OpenSSH server units were absent/inactive and no TCP/22 listener was present.

### Remote baseline

From a separate Windows Tailnet peer, the Fedora Tailscale address was scanned:

```text
22/tcp      closed
1716/tcp    open
27036/tcp   open
```

This confirmed that the broad fallback policy was not merely theoretical: services bound on high ports were reachable through the Tailnet path.

### Runtime A/B test

A temporary runtime assignment placed `tailscale0` in firewalld's restrictive `block` zone.

Fedora retained outbound Tailscale connectivity:

```text
tailscale ping desktop-rrbnrq3
-> pong
```

The same Windows scan changed to:

```text
22/tcp      filtered
1716/tcp    filtered
27036/tcp   filtered
```

This established a causal before/after relationship between the broad fallback and remote exposure.

### Permanent exact-state design

A dedicated zone was then created:

```text
workstation-tailscale
target: DROP
interfaces: tailscale0
services: none
ports: none
protocols: none
forward: no
masquerade: no
rich rules: none
```

After `firewall-cmd --reload`:

```text
wlp4s0     -> workstation-kdeconnect
tailscale0 -> workstation-tailscale
tailscale ping Windows -> PASS
```

The remote Windows scan remained fully filtered for the three tested ports.

### Reboot persistence

The Fedora workstation was rebooted.

Post-reboot validation confirmed:

```text
wlp4s0     -> workstation-kdeconnect
tailscale0 -> workstation-tailscale
tailscale status -> healthy peer visibility
tailscale ping Windows -> PASS
22/tcp, 1716/tcp, 27036/tcp -> filtered from Windows
```

The unrelated Tailscale health note about peers advertising routes while `--accept-routes=false` remains expected because subnet-route acceptance is intentionally disabled in the current client configuration.

### Repository implementation

The manually validated state is promoted into reproducible desired state through:

```text
network/tailscale-firewall-zone.sh
install.sh
scripts/verify-security-posture.sh
scripts/test_tailscale_firewall_policy.py
scripts/test_verify_security_posture.py
scripts/check-static.sh
```

The implementation preserves the broader `FedoraWorkstation` fallback zone rather than rewriting it globally. The hardening is scoped specifically to `tailscale0`.

The previous accepted physical aggregate remains historical until the updated repository completes a fresh full physical verifier run.
