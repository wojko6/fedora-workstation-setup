## User Themes v79 / 50.4

Physical inspection showed the preferences page partially in English:

```text
User Themes
Themes
Default
```

Read-only source inspection established:

- exact runtime version 79 / version-name 50.4;
- gettext domain `gnome-shell-extension-user-theme`;
- no extension-local Polish catalog;
- no matching effective entries in the checked shared system catalog;
- literal `Themes` and `Default` strings in `prefs.js`.

The first candidate localized the preference group and default row through
gettext. Visual validation then showed that the window title remained
`User Themes`.

Exact GNOME Shell source review explained the remaining gap: the preferences
dialog title is assigned directly from `extension.metadata.name`. The final
candidate therefore combines:

- a minimal gettext source patch for `Themes` and `Default`;
- a two-entry Polish runtime catalog;
- an exact-v79 metadata patch for `Motywy użytkownika` and the Polish
  description;
- pristine backups and fail-closed exact-version reconstruction.

The final UI was visually confirmed as:

Domyślny

The shared display-name manager records exact runtime version/version-name and
pristine `metadata.json` SHA-256 values. It accepts only the exact pristine
file or the exact repository-managed form obtained by changing the `name`
field. Unknown same-version metadata drift is rejected.

## Extension Manager transient failure

Immediately after the metadata edits, Extension Manager temporarily showed an
empty extension list and a generic error.

Diagnostics established that:

- `gnome-extensions list` still returned the complete extension set;
- all ten edited metadata files were valid JSON;
- all ten files contained the intended Polish names;
- the journal showed the GNOME Shell Extensions D-Bus peer disconnecting.

After restarting Extension Manager, the list returned but still showed English
names. A direct comparison then showed:

```text
DISK:  Polish name
GNOME: cached English name
```

for all ten targets.

A full GNOME session logout/login reloaded the metadata. The Polish names then
appeared correctly. No rollback was required.

## Unrelated desired-state reconciliation

The first full verifier after the localization work exposed two unrelated
runtime drifts and a network-state condition.

Space Bar had again drifted from the accepted appearance CSS to zero-radius,
zero-horizontal-padding styling. The live value was restored from
`gnome/settings.dconf`; it was not promoted.

Dhruva's folder definition matched the repository, but the live dock order had
one extra `org.gnome.Settings.desktop` item. The repository remained the source
of truth and `scripts/install-dhruva-config.sh` restored the accepted order.

The GNOME audit then completed with:

The earlier full verifier had also been run while Ethernet was the default
route, which correctly failed Wi-Fi-specific firewall and power-save checks.
Ethernet was disconnected, Wi-Fi became the default route, `wlp4s0` was
confirmed in `workstation-kdeconnect`, and `tailscale0` remained in
`workstation-tailscale`.
